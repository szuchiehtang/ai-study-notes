AGENTS.md 與 CLAUDE.md：把專案規則寫給 AI

規則檔讓 AI 每次開工都先知道專案的目的、結構與做法，新頁面才會長得一致。

本頁重點

  • 規則檔是寫給 AI 代理 (AI agent) 看的專案說明，開工時會先被讀進脈絡。
  • AGENTS.md 是開放格式，內容就是一般的 Markdown；CLAUDE.md 是 Claude Code 讀取的檔案，可以用 @AGENTS.md 匯入同一份規則。
  • 好的規則具體、簡短、可以檢查。
  • 規則檔是脈絡而不是強制設定，一定要守的規則要另外用腳本檢查。
  • Vibe coding 做出一頁；規則檔讓第二頁、第十頁還是同一個樣子。

核心概念

為什麼需要規則檔

新對話預設不會記得上一次的決定。沒有規則時，第二頁的配色、檔名與結構，全看 AI 當下怎麼猜。

規則檔把這些決定寫下來，放在專案根目錄，讓代理在動手之前先讀到。它記錄的是「這個專案要怎麼繼續做下去」。

兩種檔案

AGENTS.mdCLAUDE.md
定位引導程式代理 (coding agent) 的開放格式，可看成給代理讀的 READMEClaude Code 在每次對話開始時載入的專案指示
格式一般 Markdown，沒有必填欄位一般 Markdown，可用 @路徑 匯入其他檔案
位置專案根目錄；子資料夾可另放一份，離被編輯檔案最近的優先專案根目錄

Claude Code 的文件建議，專案已經有 AGENTS.md 時，建立一個匯入它的 CLAUDE.md，讓不同工具讀到同一份指示。本站就是這樣做：規則全寫在 AGENTS.md，CLAUDE.md 只有一行 @AGENTS.md。

規則檔該寫什麼

  • 目的：專案為誰而做，什麼才算完成。
  • 結構：每個資料夾放什麼。
  • 命名與格式：檔名、頁面區塊、資料欄位。
  • 流程：新增內容要照哪些步驟。
  • 檢查方式：做完要執行什麼指令。
  • 禁止事項：哪些檔案不能動。

AI 讀程式碼就看得出來的事不必寫。Claude Code 的文件也提醒，指示越具體、越精簡，越容易被遵守。

規則不是強制

依 Claude Code 文件的說明，CLAUDE.md 的內容是被當成脈絡，不是強制執行的設定。所以不能違反的規則要有程式把關。

本站用 tools/check.mjs 檢查檔名、區塊順序與連結，規則檔只需要寫「改完要執行它」。

實作範例

常見誤區

  • 規則寫得越詳細越好。

    冗長的規則檔會稀釋重點。只寫 AI 猜不到、而且猜錯會出問題的事。

  • 寫了規則，AI 就一定會照做。

    規則檔是脈絡而非強制。重要的規則要搭配檢查腳本或測試。

  • 規則寫一次就好。

    專案改了結構而規則沒跟著改，AI 會照著過期的規則做錯。規則檔要和程式一起更新。

自我檢核

為什麼本站的 CLAUDE.md 只有一行？

它用 @AGENTS.md 匯入規則。內容只維護一份，就不會出現兩個檔案不同步的情況。

把「頁面要整齊」改寫成可以檢查的規則。

例如：每篇筆記固定六個區塊，順序與 id 不可更動。

規則檔與檢查腳本各自負責什麼？

規則檔告訴 AI 該怎麼做；檢查腳本確認做出來的結果符合規則。
